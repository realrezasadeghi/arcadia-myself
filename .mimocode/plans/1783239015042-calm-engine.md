# Plan: Complete Sequence Diagram Implementation

## User Decisions
- **Lifeline Creation**: Both Explorer drag-and-drop + Palette panel
- **Layout Strategy**: Manual positioning (user drags, positions saved to DB)
- **Save Strategy**: Auto-save (debounced after each action)

## Current State Assessment

The sequence diagram feature has a **solid foundation** across all layers but has critical gaps that prevent it from being fully functional:

### What EXISTS (Working):
- **Domain**: `ScenarioDiagram`, `ScenarioLifeline`, `ScenarioMessage`, `ScenarioFragment` entities (complete)
- **Value Objects**: `FragmentType` (11 types), `LifelineType` (8 types), `MessageSort` (7 types) (complete)
- **DB Schemas**: 4 tables (`scenario_diagrams`, `scenario_lifelines`, `scenario_messages`, `scenario_fragments`) (complete)
- **Repositories**: 4 Drizzle repositories with full CRUD (complete)
- **Ports**: 4 repository interfaces (complete)
- **Use Cases**: 10 use cases (create/update/get/validate for all entities) (complete)
- **Server Actions**: 10 actions (complete)
- **DTOs**: Zod schemas for all operations (complete)
- **React Query Clients**: 8 client hooks (complete)
- **Basic Canvas**: `ScenarioCanvas` component with React Flow integration (partial)
- **Basic Nodes**: `LifelineNode`, `FragmentNode` (partial)
- **Basic Edge**: `ScenarioMessageEdge` (partial)
- **Store**: `ScenarioCanvasStore` with undo/redo (complete)

### What's MISSING (Gaps):

#### 1. Editor Area Integration
- `EditorArea` only renders `DiagramCanvasClient` (architecture diagrams)
- No logic to detect scenario diagram type and render `ScenarioCanvas` instead
- Scenario diagrams cannot be opened from the explorer tree

#### 2. Explorer Tree Integration
- `ExplorerTree` only handles architecture `Diagram` type
- No scenario diagram listing in the tree
- No "New Scenario Diagram" context menu option
- No way to open scenario diagrams from the tree

#### 3. Scenario Properties Panel
- No properties panel for editing lifeline/message/fragment properties
- No panel to edit message name, signature, arguments
- No panel to edit fragment guard, type
- No panel to edit lifeline selector, decomposed state

#### 4. Scenario Toolbar
- No toolbar specific to scenario diagrams
- No fragment creation button
- No message reorder controls
- No scenario validation button
- No export capabilities

#### 5. Scenario Palette
- No palette panel for scenario diagrams
- No way to add element types from palette (lifelines)
- No way to add fragment types from palette
- No way to add message types from palette

#### 6. Delete Operations
- No server action for deleting lifelines
- No server action for deleting messages
- No server action for deleting fragments
- No delete confirmation dialog for scenario elements

#### 7. Layout Persistence
- No auto-save for lifeline positions
- No auto-save for fragment positions
- No auto-save for message positions
- No viewport persistence

#### 8. Missing Use Cases
- No `DeleteScenarioLifelineUseCase`
- No `DeleteScenarioMessageUseCase`
- No `DeleteScenarioFragmentUseCase`
- No `DeleteScenarioDiagramUseCase`

#### 9. Missing Server Actions
- No `delete-scenario-lifeline` action
- No `delete-scenario-message` action
- No `delete-scenario-fragment` action
- No `delete-scenario-diagram` action
- No `update-scenario-diagram-layout` action

#### 10. Missing React Query Clients
- No `delete-scenario-lifeline` client
- No `delete-scenario-message` client
- No `delete-scenario-fragment` client
- No `delete-scenario-diagram` client
- No `update-scenario-layout` client

## Implementation Plan

### Phase 1: Backend Completeness (Delete Operations + Layout)

**Step 1.1: Add Delete Use Cases**
- File: `src/modules/model/application/use-cases/scenario/delete-lifeline.ts`
- File: `src/modules/model/application/use-cases/scenario/delete-message.ts`
- File: `src/modules/model/application/use-cases/scenario/delete-fragment.ts`
- File: `src/modules/model/application/use-cases/scenario/delete-diagram.ts`

Each use case:
1. Validates entity exists
2. For lifeline: removes associated messages
3. For message: updates fragment messageIds if in a fragment
4. For fragment: removes child fragments, updates parent
5. For diagram: removes all lifelines, messages, fragments
6. Calls repository.delete()

**Step 1.2: Add Delete Server Actions**
- File: `src/modules/model/presentation/server-actions/scenario/delete-lifeline.ts`
- File: `src/modules/model/presentation/server-actions/scenario/delete-message.ts`
- File: `src/modules/model/presentation/server-actions/scenario/delete-fragment.ts`
- File: `src/modules/model/presentation/server-actions/scenario/delete-diagram.ts`

Follow the exact pattern of existing server actions (token check, DTO parse, use case execute, ok/fail).

**Step 1.3: Add Layout Update Use Case**
- File: `src/modules/model/application/use-cases/scenario/update-layout.ts`
- Accepts: diagramId, lifelinePositions, fragmentPositions, messagePositions, viewport
- Updates all positions in a single transaction

**Step 1.4: Add Layout Update Server Action**
- File: `src/modules/model/presentation/server-actions/scenario/update-layout.ts`

**Step 1.5: Add Delete DTOs**
- File: `src/modules/model/presentation/dtos/scenario/delete.ts`
- Zod schemas for delete operations (id validation)

### Phase 2: React Query Clients

**Step 2.1: Delete Clients**
- File: `src/modules/model/ui/clients/delete-scenario-lifeline.ts`
- File: `src/modules/model/ui/clients/delete-scenario-message.ts`
- File: `src/modules/model/ui/clients/delete-scenario-fragment.ts`
- File: `src/modules/model/ui/clients/delete-scenario-diagram.ts`

Each client:
1. Uses `useMutation` with the server action
2. On success: invalidates related queries
3. On error: shows toast

**Step 2.2: Layout Client**
- File: `src/modules/model/ui/clients/update-scenario-layout.ts`
- Uses `useMutation` for layout persistence

### Phase 4: Explorer Tree Integration

**Step 4.1: Modify ExplorerTree**

- Add scenario diagram section to each model node
- Add "New Scenario Diagram" context menu option

**Step 4.2: Modify ExplorerPanel**
- File: `src/modules/model/ui/components/workbench/explorer-panel.tsx`

- Handle new scenario diagram creation

### Phase 5: Scenario Toolbar + Palette

**Step 5.1: Create ScenarioToolbar**
- File: `src/modules/model/ui/components/scenario-toolbar.tsx`
- Buttons: Add Fragment, Validate, Export, Delete Selected
- Breadcrumb: Model > Layer > Diagram Name
- Undo/Redo buttons

**Step 5.2: Integrate Toolbar in EditorArea**
- Show ScenarioToolbar when scenario diagram is active

**Step 5.3: Create ScenarioPalette**
- File: `src/modules/model/ui/components/scenario-palette.tsx`
- Element types for current layer (draggable to create lifelines)
- Fragment types (draggable to create fragments)
- Message types (draggable to create messages)
- Reuse existing `PalettePanel` pattern from architecture diagrams

### Phase 6: Scenario Properties Panel

**Step 6.1: Create ScenarioPropertiesPanel**
- File: `src/modules/model/ui/components/scenario-properties-panel.tsx`
- Context-sensitive: shows properties based on selected node/edge
- Lifeline: type, selector, decomposed toggle
- Message: name, sort, signature, arguments
- Fragment: type, guard, child fragments

**Step 6.2: Integrate Properties Panel**
- Show ScenarioPropertiesPanel when scenario diagram is active

### Phase 7: Delete Confirmation + Keyboard Shortcuts

**Step 7.1: Add Delete Confirmation**
- Use existing `ConfirmProvider` for delete operations
- Show confirmation before deleting lifelines/messages/fragments

**Step 7.2: Add Keyboard Shortcuts**
- Delete key: delete selected lifeline/message/fragment
- Ctrl+Z/Y: undo/redo (already in store, wire up)
- Ctrl+S: save layout

### Phase 8: Layout Persistence

**Step 8.1: Auto-save on Drag Stop**
- In ScenarioCanvas: onNodeDragStop triggers layout save
- Debounce saves to avoid excessive DB writes

**Step 8.2: Auto-save on Resize**
- Fragment resize triggers layout save

**Step 8.3: Viewport Persistence**
- onMove/onViewportChange triggers viewport save

## Verification Plan

After each phase:

1. **Phase 1-2**: Run `pnpm db:generate && pnpm db:migrate` to ensure schema is up to date. Test server actions in isolation.
2. **Phase 3**: Open a project with scenario diagrams. Verify they appear in the explorer tree. Double-click to open. Verify the canvas renders.
3. **Phase 4**: Verify scenario diagrams are listed under each model in the explorer. Verify "New Scenario Diagram" works.
4. **Phase 5**: Verify toolbar and palette appear when scenario diagram is active. Test all buttons. Test dragging elements from palette.
5. **Phase 6**: Select a lifeline/message/fragment. Verify properties panel shows correct fields. Edit and save.
6. **Phase 7**: Select an element and press Delete. Verify confirmation dialog appears. Confirm delete. Verify element is removed.
7. **Phase 8**: Drag a lifeline. Refresh the page. Verify position is persisted.

End-to-end test:
1. Create a project with OA layer
2. Create an OIS (Operational Interaction Scenario) diagram
3. Add 2-3 lifelines (drag from explorer OR palette)
4. Connect lifelines with messages (click source handle → target handle)
5. Add a fragment (alt/loop) from palette
6. Edit properties in properties panel
7. Auto-save triggers on drag stop
8. Refresh page - verify everything persists
